# 使用手冊

## 這是什麼

Employee Portal 是一套企業員工管理與出勤系統的展示（Demo）專案，涵蓋打卡、請假／加班／補打卡申請與審核、場地借用、員工與部門管理。這份手冊只講「怎麼用」；如果你想了解系統內部的技術決策與架構取捨，請改看專案根目錄的 `README.md` 與 `SPEC.md`，那兩份是給開發者看的。

## 展示帳號

登入頁提供「一鍵代入」按鈕，點一下就會自動代入帳密並登入，不需要手動輸入：

- 系統管理者：`admin@demo.com` / `Admin123!`
- 部門主管：`manager@demo.com` / `Manager123!`
- 一般員工：`employee@demo.com` / `Employee123!`

這三組帳密固定不變，任何時候都可以用來登入。想體驗「新帳號首次登入強制改密碼」的流程，用 `admin` 登入後到「員工資訊」建立一個新的員工帳號即可。

若展示資料被玩亂了，用 `admin` 登入後點畫面右上角的「重置展示資料」，二次確認後會一鍵清空並重新載入預設資料，完成後自動登出。

## 展示虛擬時鐘

這是一個 Demo 系統，日期固定鎖定在 **2026-08-24 至 2026-08-31** 這個展示視窗內，不會用到你電腦上的真實時間。畫面右上角有一個「展示時鐘」控制項：

- 顯示的時間會跟著真實時間持續走動（就像一個真的時鐘），不是每次都停在同一刻。
- 想跳到某個特定時間點測試功能（例如想看看晚下班會不會跳出提示），可以直接選一個日期時間、按「套用」，畫面會重新整理並套用新的時間點。
- 只有已登入的使用者才能調整這個時鐘，且調整範圍限制在展示視窗內，超出範圍會自動被拉回邊界，不會出現錯誤。

打卡、申請單的送出時間、審核時間，全部都是根據這個展示時鐘算出來的，不是你電腦的系統時間。

## 主要功能導覽

### 打卡

首頁有「上班打卡」「下班打卡」兩個按鈕。上班打卡後系統會依考勤設定判斷是否遲到；下班打卡會自動計算當天工時。如果下班時間比預計下班時間晚超過一小時，會跳出提示，詢問這段時間要算作「處理私人事務」還是要「申請加班」——選「處理私人事務」會記錄在當天的備註裡，供人資之後查核；選「申請加班」會直接帶你到加班申請表單。

### 出勤紀錄

「出勤紀錄」頁可以查自己的歷史打卡記錄，並依日期區間、狀態（正常／遲到／缺勤／早退／未打下班卡等）篩選。如果某一天的出勤有被補打卡或請假申請影響過，日期旁會有標記提醒。

### 申請單（補打卡／請假／加班）

- **補打卡**：忘記打卡時，選擇日期與要補的時段（上班／下班／兩者都補），填寫原因送出，等主管審核。同一天已經有申請中或已核准的補打卡，不能重複送出。
- **請假**：選擇假別（特別休假／事假／病假／公假）與起訖時間，系統會自動扣掉週末與國定假日，算出實際請假時數。
- **加班**：填寫加班起訖時段與事由。時數以 30 分鐘為單位計算，不足 30 分鐘的零頭不計入。加班開始時間不能早於當天正常工時結束後的一小段緩衝時間；如果當天還有申請尚未審核完，也不能送加班申請，得先等那筆申請處理完。

送出後可以在「我的申請」查看所有申請單的狀態（待審核／已核准／已駁回）。

### 審核（主管／管理者）

有審核權限的角色（部門主管、系統管理者）會在「審核中心」看到部門內待審核的申請單，可以核准或駁回並填寫備註。

### 場地借用

「場地借用」頁可以預約會議室或交誼廳，用時間軸檢視各場地目前的預約狀況，避免時段衝突——同一時段、同一場地只能有一筆有效預約。首尾相接的時段（例如 09:00–11:00 與 11:00–12:00）不算衝突，可以正常預約。

### 匯出報表（管理者／主管／被授權者）

可以匯出員工資訊、出勤紀錄（含「生效值」與「原始打卡」兩種版本）、出勤異動紀錄、場地借用紀錄，支援欄位勾選與部門／員工篩選，格式為 `.xlsx`。除了系統管理者之外，其他人的匯出範圍一律限制在自己所屬部門。

## 管理權限的個別下放

系統管理者可以把三項原本只有管理者能做的事，**個別授權給特定員工**，不需要把那個人升成管理者：

- **國定假日管理**：新增與刪除公司的國定假日
- **考勤設定**：調整上下班時間、午休時段、緩衝時間
- **匯出報表**：匯出各類報表（範圍限自己所屬部門）

操作方式：用管理者身分進入「員工資訊」頁，在要授權的員工那一列點「權限」按鈕，勾選要給的項目後儲存。該員工重新整理畫面後，側邊選單就會出現對應的功能。

幾個要知道的規則：

- 只有系統管理者能授予或收回權限。
- 權限是**即時生效**的：收回之後，對方下一個動作就會被擋下來，不需要等他重新登入。
- 每一筆授權都會記錄「是誰、什麼時候授予的」，顯示在員工資訊頁上。
- 系統管理者本來就有全部權限，不需要（也不能）對自己或其他管理者個別授權。

## 手機使用

系統支援手機瀏覽。在手機上開啟時：

- 左側選單會收起來，點左上角的選單按鈕展開。
- 資料表格會自動改成一筆一張卡片的形式，不需要左右滑動。
- 場地借用的時間軸因為需要橫向空間，維持左右滑動檢視。

## 彈性工時與緩衝時間，白話說明

系統的考勤設定裡有一個「緩衝時間」（預設 10 分鐘），它只用在「到班」這一端：

- **遲到寬限**：只要在表定上班時間之後的緩衝時間內到班，都算準時。
- **提早到班的工時起算**：如果你提早到班超過緩衝時間，系統只會從「表定上班時間 − 緩衝時間」開始算工時，不會把你提早的那一大段時間也算進去——多做的部分要認列，請另外申請加班。

同一個緩衝時間也會讓「午休」跟著你的到班時間一起微幅平移：晚到一點，午休也跟著晚一點；早到一點，午休也跟著早一點。但只在緩衝範圍內生效，超過緩衝的部分不會無限往前或往後推。

**下班這一端沒有任何寬限**：一天該做滿的工時（已經把當天核准的請假、補打卡調整算進去）就是要做滿到那一刻，不存在「差幾分鐘也算數」這回事——例如表定下班 18:00，就算你 9:00 準時上班，17:55 打下班卡一樣算早退，一定要做到 18:00 整才行。

請假時數的計算方式跟出勤打卡不完全一樣：請假的午休固定不浮動（畢竟請假通常是事先申請，當天沒有實際打卡時間可以參考），但請假的可申請時間窗一樣享有緩衝——例如你平常上班時間是 09:00，緩衝 10 分鐘，那麼從 08:50 開始的時段也可以算進請假時數。

## 本機端啟動方式

需要 Node.js、Python 3.12、Docker（跑本機 PostgreSQL）。

- 啟動本機資料庫：`docker compose up -d`
- 複製環境變數範例：`cp .env.example .env`
- 安裝相依套件：`npm install`、`pip install -r backend/requirements.txt`
- 建立資料庫結構與種子資料：`npm run db:reset`
- 啟動前後端開發伺服器：`npm run dev`

啟動後開啟 `http://localhost:5173`，用上面的展示帳號登入即可。詳細的指令與參數說明請看 `README.md`。

## 雲端部署方式

這個專案的公開展示版本部署在三個雲端服務上：

- 前端：Vercel，靜態 SPA 部署。
- 後端：Render，FastAPI 服務；使用免費方案時，長時間無人使用後第一次請求會有冷啟動延遲（通常數十秒），這是正常現象，稍等即可。
- 資料庫：Neon.tech 的 Serverless PostgreSQL。

前後端部署在不同網域，因此登入採用 Bearer Token（存在瀏覽器的 `localStorage`），而不是 Cookie——這樣不論用什麼瀏覽器開啟展示網站都能正常登入，不會受瀏覽器對第三方 Cookie 的限制影響。

## 已知限制

- 假別配額的計算公式（特別休假依到職年資、事假病假依曆年制）是寫死在後端的固定規則，不開放在畫面上自訂調整。
- 資料模型只支援「一天一筆打卡紀錄」，不支援跨越午夜的班別（夜班）。
- 申請單一經送出不能自行撤回，只能等審核結果；如果內容有誤，可以等審核完再重新提出一筆。
- 這是公開展示環境，資料庫是所有訪客共用的一份——你在系統裡新增的申請單、預約等資料，可能會在閒置一段時間後被自動重置回預設狀態，這是設計如此，不是故障。
- 「算作處理私人事務」的原因目前只會記錄成固定文字，還不支援自訂輸入內容。
- **網頁安全性（XSS）**：登入憑證（Token）存放在瀏覽器的 `localStorage`。系統本身不使用任何會略過安全轉義的渲染方式，所有使用者輸入的文字（申請原因、審核備註等）都會被正常跳脫顯示，不會被當成網頁程式碼執行；但 `localStorage` 本質上可被同網域的任何 JavaScript 讀取，若網站未來被植入惡意程式碼，憑證仍有外洩的風險。這是一個公開展示環境，請不要輸入任何真實的個人敏感資訊（例如真實姓名、身分證字號、真實聯絡方式等）。
