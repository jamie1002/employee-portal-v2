# UI／UX 規格

本文件定義視覺設計系統、版面結構、每個頁面的使用情境與元件契約，以及**響應式斷點規範**。

---

## 1. 設計系統

風格：**簡約科技風** —— Slate/Zinc 深色底板 + Neon Cyan 強調色 + 微擬態玻璃效果。

### 1.1 Design Token

Tailwind v4 為 CSS-first，全部定義在 `frontend/src/index.css` 的 `@theme` 區塊。**不建立 `tailwind.config.js`**。

```css
@theme {
  /* 底板階層（由深到淺） */
  --color-surface-950: #09090b;   /* body 背景 */
  --color-surface-900: #111114;   /* 輸入框、次級面板 */
  --color-surface-800: #18181c;   /* glass-panel 基底 */
  --color-surface-700: #26262b;
  --color-surface-600: #35353b;

  /* 邊框 */
  --color-border-subtle: #2a2a30;
  --color-border-strong: #3d3d45;

  /* 文字 */
  --color-text-primary:   #f4f4f5;
  --color-text-secondary: #a1a1aa;
  --color-text-muted:     #6b6b74;

  /* 強調色：Neon Cyan */
  --color-accent-400: #22d3ee;
  --color-accent-500: #06b6d4;
  --color-accent-600: #0891b2;

  /* 語意色 */
  --color-status-normal: #34d399;  /* 正常／成功 */
  --color-status-late:   #fbbf24;  /* 遲到／警告 */
  --color-status-danger: #f87171;  /* 錯誤／危險操作 */

  --font-sans: "Inter", "PingFang TC", "Microsoft JhengHei", system-ui, sans-serif;
}
```

### 1.2 共用樣式類別

```css
.glass-panel {
  background-color: color-mix(in srgb, var(--color-surface-800) 70%, transparent);
  border: 1px solid var(--color-border-subtle);
  backdrop-filter: blur(12px);
}
```

全站的卡片、表格容器、表單容器一律套 `glass-panel rounded-xl`。

### 1.3 全域規則

原生日期／時間選擇器的圖示在深色底上幾乎不可見，全域反轉圖示顏色（**不要**同時對個別輸入框套 `[color-scheme:dark]`，兩者疊加會再翻轉回黑色）：

```css
input[type="date"]::-webkit-calendar-picker-indicator,
input[type="time"]::-webkit-calendar-picker-indicator,
input[type="datetime-local"]::-webkit-calendar-picker-indicator {
  filter: invert(1);
}
```

### 1.4 常用元素樣式

| 元素 | 樣式 |
| :--- | :--- |
| 主要按鈕 | `rounded-lg bg-accent-500 py-2 font-medium text-surface-950 hover:bg-accent-600 disabled:opacity-50` |
| 次要按鈕 | `rounded-lg border border-border-subtle px-3 py-2 text-text-secondary hover:border-accent-500 hover:text-text-primary` |
| 危險按鈕 | 文字或邊框用 `text-status-danger`／`border-status-danger` |
| 輸入框 | `w-full rounded-lg border border-border-subtle bg-surface-900 px-3 py-2 text-text-primary focus:border-accent-500 focus:outline-none disabled:opacity-50` |
| 標籤 | `mb-1 block text-sm text-text-secondary` |
| 錯誤訊息 | `text-sm text-status-danger` |
| 成功訊息 | `text-sm text-accent-400` |
| 狀態徽章 | `rounded-full px-2 py-0.5 text-xs`，底色依語意色 |

## 2. 響應式斷點規範

**現況問題**：前一版是純桌機版面，44 個元件檔中只有 5 個有斷點處理，且全部只用在表單 grid。版面骨架、8 張寬表格、時間軸完全沒有適配。

**設計原則**：不重畫視覺，沿用既有的深色設計語言，只補斷點。採 **desktop-first 的漸進退化**（既有樣式為桌機基準，往下加手機分支）並不可行於 Tailwind（Tailwind 的 `sm:` 是 min-width），因此**改為 mobile-first**：無前綴的樣式是手機版，`sm:`／`lg:` 往上疊加。

### 2.1 斷點定義

| 名稱 | 寬度 | Tailwind 前綴 | 目標裝置 |
| :--- | :--- | :--- | :--- |
| 手機 | < 640px | （無前綴） | 375px 為驗收基準寬度 |
| 平板 | 640–1023px | `sm:` | |
| 桌機 | ≥ 1024px | `lg:` | 既有版面 |

### 2.2 全站規則

- **驗收標準：375px 寬度下，任何頁面都不得出現整頁的水平捲軸。** 個別表格／時間軸容器內部的水平捲動是允許的。
- 觸控目標最小 **44 × 44px**。
- 表單一律手機單欄（`grid-cols-1`），`sm:` 以上才多欄。
- 對話框（Modal）手機接近全螢幕、內容可捲動。

### 2.3 版面骨架（最核心的改動）

桌機版維持「左側固定側邊欄 + 右側內容區」。手機版改為：

- 側邊欄**收成抽屜**，預設隱藏；標頭左側放漢堡按鈕開關。
- 抽屜開啟時覆蓋內容區並加半透明遮罩，點遮罩或選單項目後關閉。
- 標頭元素（展示時鐘、重置按鈕、使用者姓名、角色徽章、登出）在手機上換行或收進抽屜，不可硬擠成一行。

```
桌機 (lg:)                        手機
┌──────┬──────────────┐        ┌────────────────────┐
│      │  Header      │        │ ☰  Header（可換行）│
│ Nav  ├──────────────┤        ├────────────────────┤
│ 側邊 │              │        │                    │
│ 欄   │   內容區     │        │      內容區        │
│ w-56 │              │        │                    │
└──────┴──────────────┘        └────────────────────┘
                                 抽屜由 ☰ 滑出覆蓋
```

### 2.4 寬表格的手機策略

全站有 8 張欄位數 ≥ 6 的表格（出勤紀錄、全公司出勤、員工資訊、審核中心、匯出預覽、資料庫檢視、部門管理、國定假日）。

**策略：手機改卡片式，桌機維持表格。**

- 每一列變成一張 `glass-panel` 卡片，欄位以「標籤：值」的形式縱向排列。
- 主要識別欄位（日期／姓名／標題）放大置頂，狀態徽章放右上。
- 操作按鈕放卡片底部，滿足 44px 觸控高度。
- 實作方式：同一份資料渲染兩套結構，用 `lg:hidden`／`hidden lg:block` 切換，**不要**用 JS 判斷視窗寬度（避免 SSR/初次渲染閃爍與測試困難）。

### 2.5 例外：時間軸維持水平捲動

場地借用的時間軸（08:00–20:00 × 各場地）本質上需要寬度，改成卡片會失去「一眼看出時段占用」的核心價值。

- 維持 `min-w-[720px]` + 外層 `overflow-x-auto`。
- 手機加上**捲動提示**（例如右側漸層遮罩或「← 左右滑動查看 →」文字）。
- 預約色塊高度加大以符合觸控目標。

## 3. 頁面規格

所有頁面（除 `/login`）皆包在 `ProtectedRoute` 之下：未登入導向 `/login`；`is_first_login` 為真且不在 `/change-password` 時強制導向改密碼頁。

### 3.1 導覽選單

| 順序 | 路徑 | 名稱 | 可見條件 |
| :--- | :--- | :--- | :--- |
| 1 | `/dashboard` | 首頁 | 全部 |
| 2 | `/attendance` | 出勤紀錄 | 全部 |
| 3 | `/leave-balance` | 假別 | 全部 |
| 4 | `/requests` | 我的申請 | 全部 |
| 5 | `/venue` | 場地借用 | 全部 |
| 6 | `/approvals` | 審核中心 | admin, manager |
| 7 | `/admin/employees` | 員工資訊 | 全部（通訊錄用途） |
| 8 | `/admin/departments` | 部門管理 | admin |
| 9 | `/admin/holidays` | 國定假日 | admin **或持有 `holidays.manage`** |
| 10 | `/admin/attendance` | 全公司出勤 | admin |
| 11 | `/admin/settings` | 系統設定 | admin **或持有 `settings.manage`** |
| 12 | `/admin/schema` | 資料庫管理 | admin |
| 13 | `/admin/exports` | 匯出報表 | admin, manager **或持有 `exports.run`** |

**選單過濾與頁面守門必須共用同一個判定函式**（見 §4.2 `hasAccess`），不得各自維護一份角色清單。

### 3.2 `/login` 登入頁

- **區塊**：品牌標題卡片（含「📖 查看專案說明」按鈕，強調色外框）、登入表單（電子郵件／密碼）、一鍵代入測試帳號清單（三個按鈕，右側顯示帳號）。
- **使用情境**：訪客進入 → 點「💻 一般員工 Employee」→ 自動代入帳密並登入 → 進入首頁。
- **關鍵行為**：一鍵代入**刻意不把密碼寫入 `type="password"` 欄位的 state**——Chrome 會把「密碼欄曾有值 + 表單卸載」判定為透過 JS 完成的登入而跳出「記住密碼」提示。
- **重複送出防護**：用 `useRef` 做「檢查並設定」，`useState` 只負責畫面上的 disabled 呈現（setState 無法在同一個事件迴圈內同步觀察）。
- **手機**：卡片 `max-w-md w-full`，維持單欄即可；標題與說明按鈕在窄螢幕換行。

### 3.3 `/change-password` 修改密碼頁

- 在 `ProtectedRoute` 內但**不在 AppShell 內**（無側邊欄）。
- 三個欄位（舊密碼、新密碼、確認新密碼）+ 密碼規則提示 + 「不想修改密碼？登出並換其他帳號」連結。
- 兩次新密碼不一致時**前端立即擋下**，不送出請求。
- 從登入頁導過來時，舊密碼欄已預填剛才登入用的密碼。

### 3.4 `/dashboard` 首頁

- **區塊（由上而下）**：歡迎卡片 → 打卡面板 → 本月出勤總覽 → 假別剩餘量。
- **使用情境**：員工登入 → 看到「今日尚未打卡」→ 點「上班打卡」→ 狀態卡即時更新為已打卡與狀態徽章 → 下班時點「下班打卡」→ 若晚於預計下班時間一小時以上，跳出對話框詢問「處理私人事務」或「申請加班」。
- **本月出勤總覽**：頂部先顯示「本月有 N 天異常未處理」提示（N 為異常日中還沒有任何待審申請覆蓋的天數；N=0 時不顯示這行）；下方列出當月異常日（曠職／遲到／早退／未打下班卡），每筆提供「補打卡」「請假」快捷連結（帶 `?date=` 預填）；當天已有待審申請時改顯示「已申請，待審核」。
- **申請中清單**：本月出勤總覽下方，列出目前所有待審的補打卡／請假／加班申請，統一格式為「MM/DD HH:mm(~HH:mm)　類型申請（假別，如適用）」——補打卡 `type=both` 顯示上下班時間區間，避免補打卡只顯示日期、其餘類型卻連時間都有的不一致。附「查看我的申請」連結導向 `/requests`。
- **手機**：三個卡片縱向堆疊；今日狀態卡的三欄（上班／下班／工時）改單欄或雙欄。

### 3.5 `/attendance` 出勤紀錄

- **區塊**：篩選列（起始日期、結束日期、狀態下拉）→ 出勤表格 → 分頁。
- **表格欄位**：日期（有異動申請時加標記）、上班時間（生效值被改動時加「已異動」標記）、下班時間、狀態徽章、工時、備註。
- **「顯示異動」勾選框**：勾選後對有異動的日期展開申請明細（狀態、送出時間、審核者、審核時間、駁回備註）。
- **使用情境**：員工進入 → 選狀態「早退」→ 表格只列早退的日子 → 勾「顯示異動」確認是否已有補打卡在處理。
- **手機**：篩選列縱向堆疊；表格改卡片式（日期為卡片標題、狀態徽章置右上）。

### 3.6 `/leave-balance` 假別

- 四張假別卡片（特別休假／事假／病假／公假），每張顯示期間、已用／總額／剩餘時數與進度條。
- 進度條顏色：≥90% 紅、≥70% 琥珀、其餘強調色。`公假` 不限額度時只顯示已使用時數。
- **手機**：`grid-cols-1`，`sm:grid-cols-2`。

### 3.7 `/requests` 我的申請

- 分頁籤（補打卡／請假／加班）+ 狀態篩選 + 表格。每個籤旁有「提出申請」連結。
- 狀態欄可點擊展開詳情（送出時間、審核者、審核時間、駁回備註）。
- **手機**：分頁籤可水平捲動；表格改卡片式。

### 3.8 `/requests/punch/new`、`/leave/new`、`/overtime/new` 申請表單

| 頁面 | 欄位 |
| :--- | :--- |
| 補打卡 | 類型下拉（依選擇動態顯示上班／下班時間欄位）、日期（支援 `?date=` 預填）、申請理由 |
| 請假 | 假別下拉、「整天」勾選框（自動帶入表定上下班時間）、開始／結束日期時間、**即時預估時數**、申請理由（特休可不填） |
| 加班 | 開始／結束日期時間、加班事由；支援從下班提示彈窗帶入預填值 |

- 送出成功一律導向 `/requests`；失敗在表單上方顯示錯誤訊息。
- 請假的即時預估時數是**前端本地預覽**，正式時數以後端回傳為準（演算法必須與後端一致：逐工作日交集、扣除固定午休）。
- **手機**：所有欄位單欄；日期與時間各佔一行。

### 3.9 `/approvals` 審核中心（admin／manager）

- 分頁籤（各顯示待審筆數）+ 表格（申請人、部門、申請內容、審核操作）。
- 審核對話框：「核准」直接送出；「駁回」**未填原因時確認按鈕維持停用**。
- 審核成功該筆從清單移除；遇 409（已被他人審核）顯示提示並重新載入。
- **手機**：改卡片式，審核按鈕在卡片底部。

### 3.10 `/venue` 場地借用

- 日期選擇器 + 「新增預約」按鈕 + 時間軸 + 預約詳情彈窗。
- 時間軸：08:00–20:00 橫軸、每個場地一列、預約以色塊按比例定位；**自己的預約用強調色 + 外框**與他人區隔；點空白處以 30 分鐘為刻度開啟預約表單並預填場地與時間。
- 詳情彈窗：本人的預約顯示「取消預約」；admin 顯示「強制釋放」。
- 衝突時顯示含**衝突時段與預約人姓名**的錯誤訊息。
- **手機**：時間軸維持水平捲動並加捲動提示；色塊高度加大。

### 3.11 `/admin/employees` 員工資訊

- **全角色可進入**（通訊錄用途），但依角色顯示不同內容。
- **區塊**：建立員工表單（僅 admin）→ 部門／職位篩選 → 員工表格。
- **表格欄位**：員工編號、姓名、電子郵件、職位、部門、分機、到職日 +（僅 admin）**額外權限**、操作。
- **角色下拉不提供 admin 選項**；admin 帳號那一列顯示「系統管理者帳號不提供編輯入口」。
- **部門篩選的資料來源依角色不同**：admin／manager 呼叫 `GET /departments`；employee 因該 API 回 403，改**從已載入的員工清單推導**部門選項（不為了輔助篩選去放寬 API 權限）。
- **載入用 `Promise.allSettled`**：部門查詢失敗不得拖垮員工清單。

#### 額外權限欄（新功能）

- **僅 admin 可見**。唯讀時顯示權限徽章 + 其下一行小字「由 {授權人} 於 {M/D} 授予」；無授權時顯示 `—`。
- 授權人可能已被刪除，`granted_by_name` 為 null 時顯示「已刪除的帳號」。
- 編輯時點「權限」按鈕開**獨立面板**（不是 inline 下拉，因為要容納授權紀錄），面板內是三個可勾選項目：國定假日管理／考勤設定／匯出報表。
- **面板關閉即預覽**：點「完成」關閉面板後，該列要**立刻**顯示目前的勾選結果——沿用既有授權的項目照樣顯示原本的授予人／時間，新勾選但還沒儲存的項目改標「尚未儲存」。不能讓畫面停在儲存前的舊狀態、等按下「儲存」才後知後覺地更新。
- 儲存流程：先送出員工資料更新，成功後**只在權限集合真的變動時**才呼叫權限 API（避免每次儲存都重寫稽核紀錄）——這一步才是真正把權限寫進資料庫的時間點，跟上一點的「面板關閉即預覽」是兩回事：前者只是畫面草稿，後者才是實際生效。
- **使用情境**：admin 進入頁面 → 找到某位員工 → 點「權限」→ 勾選「國定假日管理」→ 點「完成」關閉面板 → 該列立刻顯示「國定假日」徽章與「尚未儲存」→ 點「儲存」→ 徽章下方文字變成「由 系統管理者 於 9/4 授予」→ 該員工重新整理後側邊欄出現「國定假日」選單。

### 3.12 `/admin/departments` 部門管理（admin）

建立表單（名稱、主管下拉限 manager/admin）+ 表格（名稱、主管、成員人數、操作）。刪除採二次確認。

### 3.13 `/admin/holidays` 國定假日（admin 或 `holidays.manage`）

說明文字（政府行事曆需每年手動維護）+ 新增表單（日期、名稱）+ 清單（依日期排序）。刪除直接執行（無二次確認）。

### 3.14 `/admin/attendance` 全公司出勤（admin）

篩選列（**部門 → 使用者 → 狀態 → 起訖日期**，順序固定）+ 出勤表格（多顯示姓名與部門欄）。
**選擇部門後員工下拉必須連動**只列該部門成員；切換部門時若已選員工不屬於新部門則清空。

### 3.15 `/admin/settings` 考勤設定（admin 或 `settings.manage`）

- 五個欄位：上班時間、下班時間、午休開始、午休結束、緩衝時間（0–240 分）。
- 提示文字：「修改僅影響後續打卡，不回溯重算歷史紀錄」。
- 緩衝時間欄位下方需說明其語意：**同時作為遲到寬限與提早到班的工時起算基準（雙向），但早退判定不適用**。
- 前端驗證 `上班 < 午休開始 < 午休結束 < 下班`，違反時顯示對應訊息。
- 成功時顯示強調色「設定已更新」並以後端回傳值回填。

### 3.16 `/admin/schema` 資料庫管理（admin）

資料表下拉 + 「資料內容」／「結構定義」切換。資料內容顯示最新 20 筆（切換過的表快取不重複打 API）；結構定義顯示欄位名、型別、可為 NULL、主鍵、外鍵參照、預設值。

### 3.17 `/admin/exports` 匯出報表（admin／manager 或 `exports.run`）

- 資料類型下拉 → 篩選（部門／員工／日期）→ 欄位勾選 → 「預覽」與「下載 .xlsx」。
- **部門篩選只對不受限縮者顯示**（admin，或 `room-bookings` 類型）；受限縮者顯示提示「僅能匯出所屬部門資料，範圍由後端強制限定」——**文案不得寫「主管身分」**，因為被授權的可能是一般員工。
- 受限縮者的員工下拉必須只列自己部門的人，否則選到別部門會撞後端 403。
- 未勾選任何欄位時兩顆按鈕皆停用。
- 下載失敗時回應是 blob，需先轉文字解析出真正的錯誤訊息。

### 4.1 版面與守門

| 元件 | Props | 行為 |
| :--- | :--- | :--- |
| `AppShell` | — | 版面骨架：側邊欄（桌機固定／手機抽屜）+ 標頭 + 內容區。依 `hasAccess` 過濾選單 |

### 4.2 `hasAccess(user, { roles, permissions })`

**單一判定來源**，`AppShell` 的選單過濾與 `RoleGate` 共用：

```js
export function hasAccess(user, { roles, permissions } = {}) {
  if (!user) return false;
  if (roles?.includes(user.role)) return true;
  return Boolean(permissions?.some((p) => (user.permissions ?? []).includes(p)));
}
```

`user.permissions` 可能不存在（舊快取／測試 mock），必須降級為「無權限」而非崩潰。

## 5. 互動慣例

| 情境 | 慣例 |
| :--- | :--- |
| 表單錯誤 | 顯示於表單上方，取 `err.response?.data?.error?.message`，fallback 為「操作失敗，請稍後再試」 |
| 刪除操作 | 一律二次確認（「刪除」→「確認刪除」／「取消」）。例外：國定假日刪除直接執行 |
| 送出中 | 按鈕停用並改文字（「登入中...」「儲存中...」），用 `useRef` 防重複送出 |
| 載入中 | 顯示「載入中...」文字，不用 skeleton |
| 空狀態 | 表格顯示置中的說明文字（「尚無出勤紀錄」「這一天目前沒有任何場地預約」） |
| 成功回饋 | 表單類顯示強調色訊息；清單類直接反映在資料上（新增的項目出現／刪除的項目消失） |
| 權限不足 | 前端不顯示 403 頁，`RoleGate` 直接不渲染內容 |
