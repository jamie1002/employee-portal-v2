# 暖丘生活股份有限公司 — 出勤與申請作業規則

> 本文件為「員工系統 AI 聊天機器人」知識庫素材，涵蓋**出勤打卡、補打卡、加班、場地借用**四類規則，
> 逐條對應 `employee-portal-v2/SPEC.md` §4.1～§4.6 的系統實作。兩邊定義不一致時，一律以 `SPEC.md`
> 與 `system_settings` 資料表的實際值為準，本文件需同步修訂——聊天機器人不可依本文件給出與系統
> 實際判定矛盾的答案。
>
> 請假辦法與福利制度見 `leave-policy.md`；公司簡介與文化見 `company-profile.md`。

## 1. 名詞定義

回答任何出勤問題之前，先確認這四個詞的意思，它們互相依賴、不能混用：

| 名詞 | 定義 |
| :--- | :--- |
| **應到班時間** | 當日該到班的基準時刻。預設等於表定上班時間（09:00）；若當天有**從表定上班時間起連續涵蓋**的已核准請假，則往後推到請假結束時間；推完若落在表定午休內，再推到午休結束。 |
| **到班偏移量** | 實際打卡時間與應到班時間的差，**值域固定夾在 ±緩衝之內**（預設 ±10 分鐘）。晚到為正、早到為負。 |
| **工時起算點** | `max(實際打卡時間, 應到班時間 + 到班偏移量)`。準時或遲到時等於實際打卡時間；只有早到超過緩衝才會被墊高。 |
| **正常工時結束時間** | 當日「做滿了」的時刻，是早退判定與加班起算的基準。算法見 §2.4。 |

> **「應到班時間」不等於「表定上班時間」**——上午請了半天假的人，當天的應到班時間是 13:00 而不是 09:00。
> 機器人談到遲到、早退時必須用「應到班時間」這個概念，不能直接套 09:00。

## 2. 上下班打卡

### 2.1 上班打卡與遲到判定

打卡時記錄當下時間，系統自動判定當日狀態：

- **工作日**：`打卡時間 <= 應到班時間 + 緩衝` 判定為**準時（normal）**，超過即為**遲到（late）**。
- **非工作日（週末或國定假日）**：一律判定為**假日出勤（holiday_work）**，不套用遲到判定。

判定粒度是**分鐘**不是秒：09:10:00 與 09:10:59 都是「9 點 10 分」，結果完全相同；09:11:00 才算遲到。

### 2.2 緩衝只作用在到班這一端

**緩衝時間只用在上班端，下班端完全不適用**，這是刻意的不對稱設計：

- 晚到在緩衝內不算遲到，當日午休與正常工時結束時間同步往後平移。
- 早到在緩衝內，午休與正常工時結束時間同步往前平移。
- **下班沒有任何寬限**（見 §2.5）。

### 2.3 浮動午休

午休區間隨到班偏移量同步平移：09:05 到班則午休為 12:05–13:05，08:52 到班則午休為 11:52–12:52。
平移量同樣被夾在 ±緩衝之內，不會因為極晚到班而把午休推到深夜。

> **這是出勤打卡專用的規則。請假時數計算的午休固定不浮動**（一律以表定 12:00–13:00 認定），
> 兩者刻意不同，不是規則矛盾。原因是請假通常事前申請、當天沒有打卡時間可據以浮動。

若打卡時已經過了**表定**午休開始時間（12:00），系統改以「表定午休結束」為偏移量的錨點，
且不再倒給早到緩衝——上午整段已經錯過，那不叫提早到班。

### 2.4 正常工時結束時間

取以下兩式的**較小者**：

1. **封頂式** ＝ 表定下班時間 + 到班偏移量
2. **累積式** ＝ 工時起算點 + 當日應工時 + 午休長度 − 當日已核准請假時數

其中「當日應工時」＝ 表定工時 − 表定午休長度 − 當日已核准請假時數（預設情況即 8 小時）。

兩式取小的理由：只有封頂式，極晚到班的人正常工時會一路算到半夜；只有累積式，輕微遲到的人
會被完整計滿 8 小時。多數情況封頂式較小，下午請假的情況累積式較小。

### 2.5 早退判定

```
早退 = 下班打卡時間 < 當日正常工時結束時間
```

**早退沒有任何寬限**，早 1 分鐘就是早退。表定下班 18:00、09:00 準時上班的情況下，
17:55 打下班卡一樣算早退。

遲到與早退是**兩個獨立的判定**，可以同時成立（例如 09:20 到班、17:50 下班）。

### 2.6 當日工時計算

```
工時 = [工時起算點, min(下班打卡時間, 正常工時結束時間)] 區間長度 − 與浮動午休的重疊
```

工時保留到小數點後兩位。兩個直接後果：

- **超過正常工時結束時間的部分不計入當日工時**，要認列必須另送加班申請。
- **提早到班超過緩衝的部分不計入工時**：緩衝 10 分鐘、08:48 上班／12:48 下班 → 工時 3.00 小時，
  不是 3.20 小時。

非工作日（假日出勤）沒有「應到班時間」的概念，扣掉午休後的在班時間全額計入，全部視為待認列的加班。

### 2.7 忘記打下班卡

系統不會自動補。工作日有上班時間、無下班時間、且日期早於今天者，會被標記為「缺下班打卡」，
請走**補打卡申請**（見 §3）。

### 2.8 整天沒有紀錄

排程每 6 小時執行一次，回溯 60 天，對每位使用者的每個工作日，若當天完全沒有出勤紀錄，
自動補一筆狀態為**缺勤（absent）**的紀錄。已有紀錄的日子不會被覆蓋。

### 2.9 已核准的請假與補打卡不會改寫原始打卡紀錄

系統只保存「原始打卡事實」，補打卡與請假核准**不覆寫**原始紀錄，而是在查詢時即時算出「生效值」
（生效上下班時間、生效狀態、生效工時、生效早退）。因此：

- 出勤頁面上會同時看得到原始打卡時間與調整後的生效值。
- 只要當天存在**任何狀態**（待審核／已核准／已駁回）的補打卡或請假申請，該日就會被標示為「有異動」，
  即使該申請最後被駁回也一樣——這是刻意的，讓夥伴看得出這天動過。

## 3. 補打卡申請

用於忘記打卡、打錯時間的補正。

1. 於系統「我的申請」提出補打卡申請，指定目標日期與要補的上班／下班時間，並填寫事由。
2. **同一天已有「待審核」或「已核准」的補打卡申請時，不得再送出第二筆**，需等審核完成或改以修正原申請處理。
3. **補打卡的目標日期不得為未來日期**，只能補今天或今天以前。
4. 審核流程與請假相同：所屬部門主管審核（部門未指派主管時由系統管理者審核），系統管理者可審核全公司申請。
5. 駁回必須填寫理由；已審核完成的申請不得重複審核。

## 4. 加班申請

### 4.1 時數計算

- 加班時數以 **30 分鐘為單位無條件捨去**：加班 1 小時 50 分認列 1.5 小時，2 小時 29 分認列 2 小時。
- **未滿 30 分鐘的加班無法送出申請**，系統會直接擋下。
- 計算時**先扣除與表定午休（12:00–13:00）的重疊再捨去**，假日出勤橫跨午休的加班不會把休息時間算進去。
- 加班的午休固定不浮動，也不排除週末——假日出勤本來就是加班的主要來源。

### 4.2 最早可申請的起算時間

加班開始時間**不得早於**當日的「加班可認列起點」：

| 情況 | 加班可認列起點 |
| :--- | :--- |
| 工作日 | 正常工時結束時間 **+ 30 分鐘休息** |
| 非工作日（假日出勤） | 實際上班打卡時間 |

工作日那 30 分鐘休息是法規層級的規則，不是可調整的考勤設定，管理者無法把它改掉。

> 範例：09:00 準時上班、當天沒有請假，正常工時結束為 18:00，加班最早只能從 **18:30** 開始申請。

### 4.3 與其他申請的互斥

**當天只要有任何一筆「待審核」的請假或補打卡申請，就不能送出加班申請**，必須等該筆申請審核完成
（核准或駁回）之後才能申請。原因是請假與補打卡都會改變當日的正常工時結束時間，也就改變了加班的
起算基準；先送加班會讓時數認列基準在審核後又變動。

## 5. 申請單審核（三類共通）

補打卡、請假、加班三種申請單共用同一套狀態機：**待審核 → 核准／駁回**。

- 部門主管審核所屬部門同仁的申請；系統管理者審核全公司申請。部門未指派主管時，該部門一律由系統管理者審核。
- **主管不得審核自己送出的申請**。系統管理者因是系統唯一管理者、沒有代理人可審，不受此限。
- **駁回必須填寫審核備註**，不會只回一句「不行」。
- 已審核完成的申請不得重複審核，也不得逕自修改；需要調整請依駁回理由重新送出一筆新的申請。

## 6. 場地借用

- 預約時段採**半開區間**：09:00–11:00 與 11:00–12:00 **首尾相接不算衝突**，可以連續預約。
- 時段重疊時系統會擋下，並顯示衝突的時段與該時段的預約人姓名。
- **預約不得跨日**，起訖時間必須在同一天內。
- 取消：**僅本人可取消自己的預約**；系統管理者可強制釋放任何預約。

## 7. 國定假日

- 國定假日由人資部（或持有「國定假日管理」權限者）依中華民國政府公告的年度行事曆，於系統中手動維護。
- 系統**不會自動抓取**政府行事曆，需於年初手動建立當年度資料。
- 請假與加班的時數試算會自動排除國定假日，不需自行從天數中扣除。
- 任何角色都可以查詢國定假日清單。

## 8. 誰看得到什麼

| 功能 | 一般員工 | 部門主管 | 系統管理者 |
| :--- | :--- | :--- | :--- |
| 上下班打卡 | 僅本人打卡與紀錄檢視 | 僅本人打卡與紀錄檢視 | 僅本人打卡，可檢視全公司紀錄 |
| 補打卡 | 提出申請、檢視個人進度 | 加審核所屬部門同仁申請 | 審核全公司申請 |
| 請假 | 提出申請、查看假別剩餘量 | 加審核所屬部門同仁請假 | 審核全公司請假 |
| 加班 | 提出申請、查看個人核可時數 | 加審核所屬部門同仁加班 | 審核全公司加班 |
| 場地借用 | 預約、取消個人預約 | 同左 | 加強制釋放所有預約 |
| 員工資訊 | 查詢全公司通訊錄（唯讀，含分機） | 同左 | 加帳號增修刪、部門與考勤設定、權限授予 |

系統管理者可將「國定假日管理」「考勤設定」「匯出報表」三項功能個別下放給特定同仁，
被下放者的匯出範圍仍限縮在自己所屬部門。

**每個人只看得到自己的出勤與申請紀錄**，主管額外看得到所屬部門同仁的申請，跨部門一律不可見。

## 9. 展示環境的時間基準

本系統目前是**公開展示環境**，系統的「現在」不是伺服器真實時間，而是一個可由任何登入者調整的
**展示用虛擬時鐘**，範圍固定在 **2026-08-24 ～ 2026-08-31** 這個展示視窗內，超出範圍會自動夾回邊界。

所有出勤判定、申請審核時間、年資與配額計算，一律以虛擬時鐘為準。聊天機器人在回答任何與
「今天」「現在」「本月」有關的問題時，必須以系統虛擬時鐘為準，**不得使用真實世界的日期**。
